VideoGrab для Cent Browser
==========================

Что делает
----------
• Добавляет небольшую кнопку со стрелкой в левом верхнем углу видимого HTML-видео.
• Проверяет прямые MP4/WebM/MOV/MKV-ссылки коротким HEAD/Range-запросом и выбирает полноразмерный файл; маленькие сегменты и CMAF-фрагменты (в том числе .cmfv/.cfmv/.m4s/.ts) больше не скачиваются как готовое видео.
• Если прямой файл недоступен, пробует собрать незашифрованный HLS (.m3u8) из сегментов. Для master-плейлиста выбирает вариант максимального качества; если HLS разносит звук и видео по отдельным fMP4-дорожкам, пытается объединить их в один MP4 без перекодирования.
• Имеет базовую поддержку статического незашифрованного DASH (.mpd) с SegmentTemplate; при раздельных fMP4-аудио и видео дорожках объединяет их в один MP4 без перекодирования.
• Отслеживает URL медиа-запросов вкладки, чтобы находить источники у некоторых плееров, которые используют blob: URL.
• Щелчок ЛКМ по значку VideoGrab на панели расширений включает/выключает расширение. Значок и метка ON/OFF показывают состояние.

Установка в Cent Browser
------------------------
1. Распакуйте ZIP в постоянную папку, например C:\\Tools\\VideoGrab. Не удаляйте эту папку после установки.
2. Откройте в Cent Browser: chrome://extensions
3. Включите «Режим разработчика».
4. Нажмите «Загрузить распакованное расширение» и выберите папку VideoGrab (папку, в которой лежит manifest.json).
5. При необходимости закрепите VideoGrab на панели расширений, чтобы переключать его одним кликом.
6. Откройте страницу с видео, запустите воспроизведение и нажмите небольшую кнопку со стрелкой в левом верхнем углу видео.


Что изменено в версии 1.0.1
--------------------------
• Исправлен выбор источника: маленькие MP4-фрагменты, byte-range URL, CMAF (.cmfv/.cfmv) и ответы типа video/iso.segment не принимаются за целый файл.
• Проверяются Content-Length, MIME и Range/Content-Range до запуска скачивания; если загрузка всё же оказывается заметно меньше ожидаемой, файл удаляется и пробуется следующий источник.
• Расширение неизвестного вида больше не копируется из произвольного суффикса URL: например, источник с MIME video/mp4 сохраняется с расширением .mp4.
• Добавлено объединение типичных раздельных HLS/DASH fMP4-дорожек в MP4 без перекодирования. Если поток использует неподдерживаемый формат сегментов или неподходящую структуру MP4, расширение пробует следующий источник вместо создания беззвучного файла.


Что изменено в версии 1.0.2
--------------------------
• Исправлено повторное скачивание первого видео на страницах, где плеер меняет источник без перезагрузки вкладки. Прямой URL берётся прежде всего у того HTML-видео, на котором нажата кнопка.
• Из общего списка удалены старые прямые MP4/WebM-ссылки, собранные из всей истории Resource Timing страницы; оттуда остаются только timestamped HLS/DASH-манифесты.
• Сетевые наблюдения ограничены пятью минутами и отсеиваются, если они относятся к периоду до последнего успешного скачивания. Если невозможно уверенно сопоставить скрытый поток с выбранным плеером, расширение предпочитает сообщить об отсутствии подходящего источника, а не повторно скачивать старое видео.
• Источники сортируются с учётом того, относятся ли они к выбранному элементу, а для скрытых источников — по свежести запроса.
• Сообщения о ходе загрузки привязаны к конкретной кнопке/задаче, чтобы статус одного плеера не менял кнопку другого плеера.

Как это работает
----------------
• Прямые ссылки проходят проверку размера и типа содержимого. Если сервер отдаёт короткий фрагмент или ответ невозможно надёжно проверить, расширение ищет плейлист вместо сохранения фрагмента под именем MP4.
• Для HLS собираются сегменты в исходном порядке. Файлы с EXT-X-MAP / fMP4 сохраняются как MP4; обычные MPEG-TS-сегменты — как TS. Если звук находится в отдельном fMP4-плейлисте, видео и аудио мультиплексируются в один файл без перекодирования. Раздельные HLS MPEG-TS-дорожки пока не объединяются.
• Для DASH реализована распространённая схема SegmentTemplate, включая SegmentTimeline.
• Собранные HLS/DASH-файлы хранятся в памяти до формирования загрузки. Общий размер загрузки ограничен 1.5 ГБ; сборка крупных файлов всё ещё может потреблять много оперативной памяти.

Ограничения
------------
• Не обходит DRM, ContentProtection, авторизацию, платный доступ, шифрованные HLS-плейлисты или другие механизмы защиты. Такие потоки пропускаются.
• Не каждый сайт раскрывает URL видео расширению: некоторые плееры используют закрытые shadow DOM, нестандартные протоколы, токены/заголовки с коротким сроком жизни или серверные ограничения.
• HLS live-поток без EXT-X-ENDLIST сохраняется только в виде доступных на момент нажатия сегментов — это не запись будущего эфира.
• DASH BaseURL/SegmentTemplate реализован для типичных статических MPD. Схемы SegmentList, SegmentBase, DRM и динамический live DASH не поддержаны. Для отдельных аудио/видео fMP4-адаптаций выполняется объединение; нестандартные структуры, которые нельзя безопасно объединить, пропускаются.
• Если источник зависит от нестандартных заголовков Referer/Authorization, браузер может отказать в загрузке.
• Расширение не загружает ничего само по себе: загрузку запускает нажатие на кнопку у видео.

Конфиденциальность
------------------
Расширение локально запоминает ограниченный список URL запросов, похожих на медиа, для текущих открытых вкладок. URL никуда не отправляются и используются только для поиска источника видео. При закрытии вкладки соответствующий список удаляется.

Файлы
-----
manifest.json  — настройки расширения
background.js  — поиск источников, скачивание прямых файлов и сборка потоков
content.js    — кнопки поверх видеоплееров и сбор метаданных
icons/        — значок расширения для состояний ВКЛ/ВЫКЛ
